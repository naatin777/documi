# Web UI 基盤として Base UI (`@base-ui/react`) と Tailwind CSS v4 を採用する

<Decision id="dec.base-ui-tailwind" stability="stable">
  Documi Web UI のアプリ殻（レイアウト・サイドバー・タブ・インスペクタ・各種ビュー・ダイアログ・メニュー・ポップオーバー・ツールチップ）は **`@base-ui/react`（ヘッドレス UI プリミティブ）＋ Tailwind CSS v4（`@tailwindcss/vite`）** で構築し、旧アプリ殻 CSS（`layout.css` / `panels.css` / `views.css` / `modals.css` / `responsive.css`）および互換レイヤは廃止する。MDX 本文組版・セマンティックブロック装飾・PDF/HTML 印刷（`tokens.css` / `document.css` / `semantic.css` / `print.css`）のみを素のセマンティック CSS として維持し、視覚付き総合 UI ライブラリ（MUI / Ant Design 等）は採用しない。
</Decision>

## 背景と課題

- 既存の `src/web/styles/*.css` が約 5,000 行規模まで膨らんでおり、UI 機能追加のたびに別ファイルの CSS と JSX を往復する必要があり、不要クラスの取り残しやカスケード干渉が起きやすかった。
- モーダル（検索 / Export / Mermaid 拡大）・ドロップダウン（開いているタブ一覧 / 言語切替）・用語ホバープレビュー（`TermPopover`）・ツールチップを手書き実装していたため、フォーカストラップ・背面スクロールロック・ビューポート端での反転配置・キーボード操作の保守コストが増えていた。
- 未リリース期間中に旧 CSS 互換レイヤを残すと二重管理が固定化するため、アプリ殻のスタイルは一括で Tailwind CSS v4 へ整理する。

## 設計方針

1. **CSS レイヤ構成 (`src/web/styles.css`)**
   - `tailwindcss/theme.css`（`theme`）、`tokens.css`（`base`）、`document.css` / `semantic.css` / `print.css`（`components`）、`tailwindcss/utilities.css`（`utilities`）の 4 層で読み込む（Preflight なし）。
   - Markdown リスト・見出しウェイト・KaTeX・`@media print` の組版品質をそのまま保ちつつ、全アプリ殻 UI を Tailwind ユーティリティで完結させる。
   - `tokens.css` の CSS 変数（`--bg`, `--bg-sidebar`, `--border`, `--text`, `--text-muted`, `--text-faint`, `--accent` 等）を `@theme inline` で Tailwind カラーへ直結させ、`[data-theme="dark"]` を `@custom-variant dark` で連動させる。
2. **共通ヘッドレスプリミティブ (`src/web/components/ui/`)**
   - `Dialog`（`AppDialog` / `DialogClose`）・`Tooltip`（`TooltipProvider` / `AppTooltip`）に加え、`@base-ui/react/menu`・`popover`・`preview-card` を活用し、SSR (`renderToStaticMarkup`) でも安全に動作するよう Portal の有無をガードする。
