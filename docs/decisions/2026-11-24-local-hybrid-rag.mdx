# ローカル Hybrid RAG（BM25 + RRF + Ollama / OpenAI 互換 HTTP + bun:sqlite 差分キャッシュ）を採用する

<Decision id="dec.local-hybrid-rag" stability="stable">
  Documi の高度な文脈検索（<Term name="HybridRAG" />）は **2 段階のローカル完結構成** を採用する。（1）依存ゼロの日本語・英語・識別子 BM25 トークナイザ ＋ `<TermDef aliases>` 自動同義語展開 ＋ 明示グラフ展開（`documi search --context` / MCP `search_documents(includeContext: true)`）を標準基盤とし、（2）セマンティック検索は `.documi.json` の `rag` 設定または `--semantic` による **オプトイン** として、ネイティブ ML 依存を持たない HTTP プロバイダ（Ollama 既定 `embeddinggemma`・OpenAI 互換 HTTP）と `bun:sqlite` 差分キャッシュ（`.documi/cache/embeddings.sqlite`）を RRF で統合する。プロバイダ障害時は必ず BM25 結果へ安全にフォールバックし、**検索対象は `docs/` のみ** とする（ソースコードは `<SourceRef>` / `@implements` から辿る）。
</Decision>

## 背景と課題

- 仕様書が増えてくると、AI エージェントが「Spec ID を知らない自然文タスク」から関連文書を探す際、単純な部分一致では日本語表記揺れ（例: 承認記録 / サイドカー / レビュー）や抽象的な概念質問を取りこぼしやすい。
- 一方で、外部クラウド Embedding API や別プロセスのベクトル DB（Qdrant / Chroma 等）を必須要件にすると、Documi の強みである「ローカル単一バイナリ・ゼロ設定・オフライン動作・プライバシー保護」が壊れる。
- また、ソースコード全文までベクトル DB へ格納すると、チャンクの陳腐化・インデックス肥大・仕様とコードの二重管理を引き起こす。

## 検討した選択肢と棄却理由

- **採用: 依存ゼロ BM25＋用語展開＋グラフ展開を基盤にし、オプトインのローカル Hybrid RAG を重ねる**
  - 日常の既定検索は起動コスト・ダウンロードゼロで即座に動作する。
  - セマンティック検索は外部 ML ネイティブ依存（`@huggingface/transformers` / `onnxruntime-node` 約 460MB）を本体へ同梱せず、標準 `fetch` による Ollama / OpenAI 互換 HTTP プロバイダに絞ることで、インストール軽量化と単一バイナリ配布（`bun build --compile`）との両立を実現する。
  - ローカル実行の既定モデルに Ollama `embeddinggemma` を採用し、モデル系列別プロンプト接頭辞（EmbeddingGemma / Qwen3-Embedding / ruri）に対応することで日英混在仕様の検索精度を確保する。
  - `bun:sqlite` に `contentHash` 単位でベクトルをキャッシュするため、編集された文書・ブロックのみを差分再計算できる。
- **棄却: クラウド Embedding API（OpenAI / Gemini API）のみ対応する**
  - API キー管理と社外への仕様送信が必要になり、ローカル完結・機密仕様リポジトリでの利用を阻害する（ただし OpenAI 互換 HTTP は選択肢の 1 つとしてサポートする）。
- **棄却: 外部ベクトル DB サーバーを前提にする**
  - ローカル開発環境でのセットアップ摩擦が大きすぎ、`goals/low-friction-governance` に反する。`docs/` 規模（数百〜数千チャンク）では `bun:sqlite` + 正規化 `Float32Array` 内積走査でミリ秒単位に収まる。
- **棄却: ソースコード全文をチャンキングしてベクトル検索対象に含める**
  - コード検索は既存のエディタ・`rg`・AST 解析の方が正確であり、Documi は `docs/` 内の構造化仕様から `<SourceRef>` / `@implements` 経由でコードへ正確に辿る役割に徹するべきである。

## 影響とガードレール

- `docs/.documi/cache/embeddings.sqlite` は再生成可能な派生キャッシュであり、`.gitignore` 対象とする（Git にコミットしない）。
- モデル・プロバイダ・量子化設定の変更は `model_key` 単位で管理し、古いキャッシュとの混在を防ぐ。
- Embedding プロバイダが利用不可（ネットワーク未接続の初回実行・Ollama 未起動・API エラー等）であっても、検索自体を失敗させず BM25 + グラフ展開へフォールバックし、結果の `mode` / `fallbackReason` で透過的に通知する。
