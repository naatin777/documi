# MDX 細切れセマンティックタグと Rooted DAG + Sigma.js グラフ構造の採用

<Outcome id="dec.semantic-graph" stability="stable">
  文書内部を `<Spec>` / `<Constraint>` / `<Outcome>` / `<Note>` / `<TermDef>` のセマンティックタグで細切れに構造化し、ブロック単位のドット区切り ID を付与する。グラフは **本文リンク・用語からの自動接続 (`mentions`)** と **トレーサビリティ用の意味付き辺 (`derives` / `satisfies` / `verifies` / `supersedes`)** のハイブリッドとし、`normative` な `<Spec>` は `goal` を根に持つ Rooted DAG を必須とする。グラフ可視化には WebGL ベースの **Sigma.js + Graphology + リアルタイム力学シミュレーション** を採用する。
</Outcome>

## 背景と根拠

### 1. なぜ MDX で細切れのタグで囲むのか
- AI エージェントは仕様を一気に長文で生成する傾向があり、ファイル単位の管理だと「このファイルの 3 段落目だけまだ人間が承認していない」「この要件だけ将来変わる可能性が高い」を表現できない
- 意味のある最小単位を MDX タグで囲むことで、人間は視覚的カードとして読みやすく把握でき、ツール・AI は AST (`mdast`) からブロック単位でハッシュ算出・承認・テスト紐づけ・検索ができる
- 任意 JS 実行は禁止し、許可リスト制の静的属性（文字列リテラル）のみを扱うことで安全性を保つ

### 2. なぜ「文章内参照だけのグラフ」ではなく意味付きエッジ + Rooted DAG か
要件工学標準 **SysML** の知見（`deriveReqt` / `satisfy` / `verify` / `trace`）に基づき、エッジを 5 種類に分けた：
- 文章中のリンクをすべて同じ無ラベル辺にすると、用語集や共通ガイドに全ページが繋がってグラフがすぐスパゲッティ化し、影響分析やテスト網羅率の算出ができない
- 一方で全リンクを frontmatter に手書きさせると二重管理で破綻する
- そこで **普段の参照は本文 Markdown リンク・用語から `mentions` として自動抽出** し、**トレーサビリティの背骨 4 種だけ明示** するハイブリッド方式を採用した
- さらに `normative` な `<Spec>` が `derives` で `goal` に遡れない場合は `orphan-spec` とすることで、AI が勝手に仕様を膨らませる脱線を防ぐ

### 3. なぜグラフ可視化に Sigma.js を採用したか
- 文書・セマンティックブロックが増えて数百ノード規模になっても、WebGL レンダリングとリアルタイム力学シミュレーション（中心引力・反発力・エッジばね引力）により Obsidian Graph View のように滑らかに展開・弾性ドラッグ・パン・ズーム・ホバー近傍ハイライトができる
- 静的な図ではなく「クリックして関連ノードだけ浮かび上がらせる」「Traceability Only と All Links を切り替える」「文書単位とブロック単位を切り替える」インタラクティブな探索体験が、人間がシステム全体を理解する上で最も効果的である
