# Web UI アーキテクチャと Side-by-Side 閲覧設計

## 1. レイアウト構造と遅延ロード（Code Splitting）

- 画面全体は左サイドバー（`Explorer`・既定 280px、`⌘B` またはタブバー左端トグルで開閉。折りたたみ時はワークスペースが画面幅 100% へ広がる）と右側ワークスペース（`.workspace`：上部に常設の統合 `<DocTabs />`、下部に `.doccols` Flex 横並び）の 2 領域で構成する。
- `<DocTabs />` は `Home`・`Review Queue`・`Graph`・`Code Explorer`・各ドキュメントをすべて対等なワークスペースタブとして統一管理し、左端にサイドバー開閉ボタンを常設する。タブ幅は縮めない（`flex-shrink: 0`）設計のまま、横スクロールバーを非表示にしてホイール横スクロール・左右端フェード＆`‹`/`›`ボタン・右端の開いているタブ一覧ドロップダウンで操作性を確保する。
- 左サイドバー・右 Context Inspector (`SidePanel`)・Side-by-Side プレビュー (`DocPeekPane`) の各境界には共通の `ResizeHandle` を配置し、ドラッグ伸縮（ダブルクリックで既定幅リセット、`localStorage` 永続化）に対応する。
- `.doccols` 内に `<main className="content">` と条件付きの `<aside className="side-panel">` を並べることで、右ペインが不要な画面（Home / Review 未選択 / Graph 未選択）では中央が自動的に全幅へ広がる。
- `OverviewLayout` / `ReviewLayout` / `DocLayout` / `GraphLayout` / `BundleLayout` / `SearchModal` は `React.lazy()` + `Suspense` でルート単位に Code Splitting し、Sigma.js や Markdown/KaTeX パーサーを該当画面でのみ読み込むことで初期メインバンドルを約 80% 削減している。

- **アイコンとタイポグラフィ**: 全画面の UI アイコンおよび 7 種 Artifact Type アイコンを `lucide-react`（均一ストローク）へ統一し、オリジナル幾何学マーク（`BrandMark` / `public/favicon.svg`）を配置する。Code Explorer および Docs Explorer（Files モード）・`<SourceRef>` のファイル／フォルダ一覧には `material-icon-theme`（VS Code Material Icon Theme 公式 SVG）を `/api/icons/manifest`・`/api/icons/:name` 経由でオンデマンド配信して表示し、クライアントバンドル肥大を防ぎつつライト／ダーク自動切替に対応する。本文は `@fontsource/ibm-plex-sans` + `@fontsource/ibm-plex-sans-jp`、コード・Spec ID・数値は `@fontsource-variable/jetbrains-mono` をローカル同梱し、オフラインおよび PDF Export でも同一の組版品質（見出し詰め組み `palt`・等幅数値 `tabular-nums`）を保つ。

- **多言語対応 (i18n)**: `i18next` + `react-i18next` を採用し、`src/web/locales/en.json` をマスター（フォールバック言語）として `en` / `ja` を提供する。初回はブラウザ言語を自動検出し、ヘッダーの言語切替ドロップダウン（`LanguageToggle`）で `localStorage` 保存と `<html lang>` 同期を行う。新言語の追加は JSON 1 ファイル追加と `SUPPORTED_LOCALES` への 1 行登録で完結し、`tests/i18n.test.ts` が全ロケールのキー・プレースホルダ整合性を自動検証する。

## 2. 1 本サイドバー（Flow / Files）と専用 Review Inbox (`/review`)

- `Explorer` の上部に 4 大ビュー（`Home` / `Review Queue`（要確認件数バッジ付き）/ `Graph` / `Code Explorer`）を固定配置し、下部にドキュメント一覧の **Flow（上流→下流の読み順）** と **Files（フォルダ階層）** 切替を置く。
- `ReviewLayout` (`/review`) は `GET /api/blocks` から全レビュー対象ブロックを取得し、`要確認 (Stale / Suspect)`・`未解決フィードバック`・`未承認`・`承認済み`・`すべて` のタブで絞り込みながら、インライン Diff 表示・ワンクリック承認・右側「並べて確認」を提供する。

## 3. Context Inspector と共通 Side-by-Side プレビュー (`DocPeekPane`)

- `/docs/*` の右ペイン (`SidePanel`) は `Outline`（承認/検証サマリバー・Blocks・見出し目次）と `Links`（上流・前提 / 下流・依存元 / 関連コード `SourceRefs` / 言及）の 2 タブで構成する。
- `Links` の分割ボタン（または `Shift+クリック`）、`/graph` でのノードクリック、`/review` の「並べて確認」はいずれも共通の `DocPeekPane` を右ペイン（幅 `clamp(380px, 44%, 640px)`）に開き、見出し ID 衝突を避けるため `headingPrefix="peek"` 付きで MDX 本文・用語ポップオーバー・承認 UI をそのまま描画する。

## 4. Hono RPC クライアント・React Query キャッシュと SSE ライブ更新

- `src/web/api.ts` は `hc<ApiRoutes>('/')` と `InferResponseType` によりサーバー側ルート定義（`src/server/app.ts`）からレスポンス型を直接推論し、フロント側の手書き型二重管理を排除している。
- `src/web/queries.ts` が `@tanstack/react-query` ベースの共通クエリフック群を提供し、タブ切替や再訪時の重複フェッチを抑制する。`LiveProvider` が `/api/events` の SSE を購読し、ファイル変更・承認・テスト結果更新時の `reload` イベントで `queryClient.invalidateQueries()` を実行して全画面をライブ再描画する。
- **UI プリミティブとスタイリング**: アプリ殻のレイアウト・ビューおよびインタラクティブ部品（ダイアログ・メニュー・ポップオーバー・用語ホバープレビュー・ツールチップ）は **`@base-ui/react`**（`src/web/components/ui/Dialog.tsx`・`Tooltip.tsx` および `Menu` / `Popover` / `PreviewCard`）と **Tailwind CSS v4**（`@tailwindcss/vite`、`tokens.css` を `@theme inline` へ直結）で構成し、旧アプリ殻 CSS・互換レイヤを廃止している。MDX 本文組版・セマンティックブロック・PDF 印刷（`tokens.css` / `document.css` / `semantic.css` / `print.css`）のみを素の CSS として保持する（詳細は [Base UI + Tailwind CSS v4 採用 ADR](../decisions/2026-11-base-ui-and-tailwind-v4.mdx)）。
- **コードハイライト**: `src/web/highlight.ts` は `shiki/core` + JavaScript Regex エンジンで主要開発言語と 2 テーマのみをオンデマンド遅延読込する。

## 5. 読み取り専用 Code Explorer (`/code`)

- `src/core/code.ts` が `projectRoot` 配下のソースファイルツリー（`buildCodeTree`）と全文＋逆リンク集約（`readCodeFile`）を提供し、`/api/code/tree`・`/api/code/file` 経由で配信する。
- `CodeExplorerLayout` は左側に開閉・伸縮可能なファイルツリー（Material Icon・階層ガイド線・仕様リンク絞り込み付き）、中央に Shiki 行番号ハイライト＋行クリック範囲選択＋行内 Spec バッジ付き読み取り専用ビューア、右側に開閉・伸縮可能なインスペクタ（`シンボル` タブの AST 公開シンボル一覧ジャンプ／`関連` タブの Spec・Doc・Term 逆リンク）および共通の `DocPeekPane` を組み合わせ、ソースコードと仕様書を並べて閲覧できる。
- `<SourceRef>`・`SidePanel` の `Source Refs`・`BlockReviewControls` の実装/テスト箇所リンクから `/code?file=...&line=...` へ双方向ジャンプできる。

## 6. ドキュメント鮮度・最新変更ハイライト・過去版 Side-by-Side 閲覧

- Overview・Explorer・文書ヘッダーに `Document.freshness`（作成日時・最終更新日時・未コミット変更マーク）を表示する。
- 文書閲覧時は `GET /api/history` から取得した本文基準の変更行レンジと mdast 要素の行範囲を照合し、最新変更箇所の左アクセントバーと目次ドットを強調表示する（ツールバーから ON/OFF 切替可能）。
- `SidePanel` の `History` タブで過去コミットを選択すると `GET /api/history/revision` から該当版を取得し、共通の `DocPeekPane` 領域へ現在版と並べてレンダリングする。
- 静的サイトモード（`window.__DOCUMI_STATIC__`）時は `HashRouter` と静的 JSON アダプタへ自動切替し、SSE ライブ更新や承認操作を無効化した読み取り専用ビューアとして動作する。
