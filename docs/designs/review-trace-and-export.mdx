# レビュー・トレース・複数まとめ Export の設計

## 1. サイドカー承認と Git Diff

- 人間の承認状態は MDX 本文ではなく `docs/guard/reviews.json` にキー昇順 JSON で保存し、AI による MDX 直書きと物理分離する
- 承認時に `contentHash`・`approvedCommit`・`upstreamHashes`・任意の確認メモ（`note`）を記録し、同時に `.documi/cache/approved-bodies.json`（`.gitignore` 対象）へ本文キャッシュを保存する
- `stale` 発生時は `git show <approvedCommit>:<path>` から承認時点のブロック本文を取り出し、未コミット承認時はローカルキャッシュへフォールバックして LCS 行 diff を算出する

## 1.5 machine Signal の評価

- `<Signal method="machine">` は check 実行時に、確定済みの errors / warnings / realizationCounts / reviewCounts を閉じた語彙のメトリクスとして参照し、`op`・`value` で比較して達成／未達を算出する
- 評価は check の全エラー・警告が確定した後に行う（`check.errors` / `check.warnings` メトリクスが自己言及で不安定にならないよう、評価自体は新たなエラーを生まない）
- 未達は内部整合性のエラーではなく目標未達の観測であるため、`ok`／終了コードに影響させず独立セクションで報告する

## 2. コード・テスト・PR からの Realization 自動算出

- ソース/テストファイルから `@implements` / `@verifies`（コメント部のみ）および行頭の `test("[<spec.id>] ...")` を抽出し、`<SourceRef>` の `satisfies` / `verifies` と統合する
- JUnit XML (`.documi/test-results.xml`) の `<testcase name="[spec.id] ...">` と突合し、さらに任意で `gh pr list` の PR 情報を重ねて `verified` / `implemented` / `in-progress` / `unimplemented` / `drifted` を決定論的に算出する

### ドキュメント健全性・カバレッジ算出 (`src/core/health.ts`)

- `computeDocumentHealth()` が `normative` `<Spec>` の Design / `<Test>` カバレッジ・Spec ファイル肥大化（既定安全網 10 件超）・過密 `design` ハブ・全体設計（`design` / `scope: system`）鮮度差・禁止語混入・`<SourceRef>` の脆い結合（`lines=` / `design` 外配置）を純粋計算し、CI を落とさない Advisory ヒントとして CLI・MCP・Overview UI へ供給する
- Git 作業ツリー上で `src/` / `.agents/skills/` に変更があるのに `docs/` 未更新のシグナルは `collectWorkspaceHealthSignals()` が安全に収集し、`computeDocumentHealth()` へ渡して統合する（非 Git 環境では安全にスキップ）

## 3. `/bundle` × `Bun.WebView.navigate()` による複数まとめ Export

- 単一文書用の DOM クローン POST 方式は 5MB 上限や非表示文書・`<Tabs>` 欠落の制約があるため、複数文書は React 側の専用ルート `/bundle` を使用する
- `/bundle` は表紙・自動目次・章区切り・ページ内アンカー変換・見出し ID 名前空間化・`<Tabs>` 全展開を行い、Mermaid / Shiki / `<SourceRef>` の描画完了時に `window.__DOCUMI_BUNDLE_READY__ = true` を立てる
- サーバー (`/api/export/bundle-pdf`) および CLI (`documi export`) は `Bun.WebView({ backend: 'chrome' })` でローカルループバックの `/bundle?...` を直接開き、CDP `Page.printToPDF` で PDF を生成する（ループバック `/bundle` 以外の URL は SSRF 防止のため拒否）
