# MCP ツールコントラクト

AI エージェント向けに **2 種類のトランスポート** で同一のツール群を提供する（設計根拠: [同一リポジトリ原則・Code Explorer・MCP 精密編集ハイブリッド ADR](../decisions/2026-11-code-explorer-and-mcp-editing.mdx)）。`McpServer` は初期化レスポンスの `instructions` に段階的コンテキスト取得・精密編集・不変ルール（`reviews.json` 改変禁止・MDX 安全性）・`validate_docs` 実行手順を自己完結で内蔵するため、Agent Skills を併用しない MCP クライアント単体でもそのまま運用できる。

- **Streamable HTTP (`POST /mcp`)**: `documi serve` 起動時に Stateless（`enableJsonResponse: true`）で提供
- **stdio (`documi mcp`)**: サーバー常駐なしで Claude Code / Cursor / Antigravity 等から直接起動し、`fs.watch` で最新 `docs/` を自動反映

## 読み取り・検証ツール（副作用なし）

| Tool | 入力 | 役割 |
|---|---|---|
| `get_project_map` | `full?` | Goal / System Design（`design` + `scope: system`）概要・現行独立 `<Decision>` 結論一覧（廃止済みは `supersededDecisions` へ分離）・Domain 用語集・Review & Realization サマリを一括取得（`full: true` で全文展開） |
| `list_documents` | `type?`, `mount?` | ドキュメントサマリ一覧を取得（`mount` で複数 docs 構成のマウント絞り込み可） |
| `get_document` | `id` | パス ID から本文・セマンティックブロック（`startLine` / `endLine` 含む）・関係・問題一覧を取得 |
| `get_relations` | `id` | ドキュメント ID またはブロック ID の外向き/逆参照を取得 |
| `get_impact` | `id`, `maxDepth?` | 指定ドキュメントまたはブロックを変更した際に影響する下流文書・ブロック・`<SourceRef>`・コード／テスト参照を再帰走査で一覧化（既定 `maxDepth: 4`） |
| `query_specs` | `kind?`, `intent?`, `stability?`, `review?`, `realization?`, `suspect?`, `mount?`, `query?`, `full?` | セマンティックブロックを多軸フィルタ検索（既定は `docPath`・`startLine`・`endLine`・要約付き軽量サマリ、`full: true` で詳細配列込み） |
| `get_spec_context` | `id`, `full?` | 指定 Spec の本文・`docPath`・`startLine`・`endLine`・上流 Goal 概要・関連 Design/Contract・`<Decision>` 結論（マイクロ ADR 含む）・関連用語・`<SourceRef>` を一括集約（`full: true` で完全展開） |
| `search_documents` | `query`, `type?`, `mount?`, `limit?`, `semantic?`, `includeContext?`, `budget?`, `includeGraph?` | ドキュメントとセマンティックブロックを BM25＋用語集同義語展開（`semantic: true` または `rag.enabled` 時はローカル Embedding＋RRF）で横断検索。`includeContext: true` 時は上流 Goal・`<Decision>` 結論・関連 Contract/Design・用語・`<SourceRef>` を文字数予算内で 1 発展開 |
| `validate_docs` | なし | `orphan-spec`・参照切れ・循環・重複 ID・MDX 未対応構文・AST `<SourceRef>` / `<TermDef>` シンボル切れを一括検証 |

## 精密編集・構造操作ツール（Surgical Write）

AI が 1 ブロック修正するために無関係な文書全体を読み込むコンテキスト汚染を防ぐため、AST 位置ベースの局所編集および参照一括更新ツールを提供する。

| Tool | 入力 | 役割 |
|---|---|---|
| `update_block` | `id`, `body`, `title?`, `summary?`, `date?`, `level?`, `verifies?`, `stability?`, `intent?`, `derives?`, `supersedes?`, `scope?`, `aliases?`, `symbols?` | 既存セマンティックブロック（`<Spec>` / `<Constraint>` / `<Decision>` / `<Test>` / `<TermDef>` / `<Note>`）の該当行範囲のみを更新し、再読込後の検証結果を返却 |
| `add_block` | `docId`, `kind`, `id`, `body`, `afterHeading?`, `title?`, `stability?`, `intent?`, `derives?`, `supersedes?`, `scope?`, `aliases?`, `symbols?` | 指定ドキュメント末尾（または指定見出し直下）にセマンティックブロックを 1 件追記し、検証結果を返却 |
| `upsert_term` | `id`, `definition`, `aliases?`, `symbols?`, `docId?` | 用語集（既定: `domain/glossary`）に `<TermDef>` を追加または更新し、検証結果を返却 |
| `scaffold_document` | `path`, `title`, `mount?`, `type?`, `description?`, `date?`, `tags?`, `derives?`, `satisfies?`, `verifies?`, `body?` | 規約通りの YAML frontmatter を持つ新規 `.mdx` ドキュメントを作成（既存ファイルの上書きは拒否、`mount` 省略時はプライマリへ出力） |
| `rename_block_id` | `oldId`, `newId`, `dryRun?` | 全 `docs/` のブロック定義・`derives` / `supersedes` / `satisfies` / `verifies`・`<SourceRef>` と、`projectRoot` 配下の `@implements` / `@verifies` / `test("[id]")` を一括リネーム（`dryRun: true` で変更予定一覧のみ返却） |

## コンパクト出力 vs `full: true` 契約

AI のコンテキスト消費を抑えるため、主要読み取りツールは既定で軽量サマリを返し、`full: true` 指定時のみ完全展開する。

| Tool | 既定 (`full: false`) の主要返却構造 | `full: true` で追加展開される項目 |
|---|---|---|
| `get_project_map` | `documentCount`, `blockCount`, `issueCount`, `reviewSummary`, `realizationSummary`, `health`, `goals`（概要＋見出し）, `goalConstraints`（`goal` 内 `<Constraint>`）, `systemDesigns`（`scope: system` の `design` 概要＋見出し）, `domainModels`（ドメインモデル概要＋見出し）, `domainInvariants`（`domain` 内 `<Constraint>`）, `decisions`（現行独立 `<Decision>` の結論のみ・240 字要約）, `supersededDecisions`（廃止済み・`supersededBy` 付き）, `terms`（`aliases` / `antiTerms` / `context` / 160 字要約） | `goals[].body`, `goalConstraints[].body`, `systemDesigns[].body`, `domainModels[].body`, `domainInvariants[].body`, `decisions[].body` 全文, `terms[].definition` 全文 |
| `query_specs` | `{ count, blocks: [{ id, kind, docId, docPath, startLine, endLine, intent, stability, review, suspect, realizationStatus?, derives?, level?, verifies?, summary }] }` | 各ブロック全文 `rawBody`・完全な `realization` 詳細配列 |
| `get_spec_context` | `target`（本文＋要約 `realization`）, `docPath`, `startLine`, `endLine`, `document`, `upstreamGoals`（概要）, `relatedDocuments`（概要）, `decisions`, `tests`（対象 Spec を `verifies` する `<Test>` 一覧）, `relevantTerms`（160 字要約）, `sourceRefs`, `exportedSymbols?`（`mode="exports"` 参照のみ） | 上流 Goal 本文全文・完全な `realization` 配列・全 `sourceRefs` ファイルの公開シンボル |
| `search_documents`（`includeContext: true`） | `{ query, mode, budget, usedChars, hits, upstreamGoals, decisions, relatedDocuments, terms, sourceRefs }`（既定 `limit = 8`, `budget = 6000`、廃止済み ADR は除外） | —（`budget` で上限調整） |

## 事前・事後条件・副作用・エラー規約

- **読み取りツールの純粋性**: 読み取り・検証ツールは完全に読み取り専用であり、MDX 本文・`docs/guard/reviews.json`・ソースコードを一切書き換えない。
- **書き込みツールの副作用境界（絶対不変）**:
  - 変更対象は `docs/` 配下の `.mdx` / `.md`（および `rename_block_id` 実行時に限り `projectRoot` 配下の対象ソース・テストファイル）に厳格に限定する。
  - **`docs/guard/reviews.json`・`docs/guard/`・`.documi/` 配下は一切変更しない**（人間の承認変更は Web UI / CLI 専用）。
  - 書き込み成功後は `DocsStore.reload()` を実行し、最新の `issues` / 検証サマリをレスポンスに含めて返す。
- **事前検証とロールバック**:
  - すべてのツール引数は Zod スキーマで検証し、型・必須項目・ブロック ID 形式（`BLOCK_ID_PATTERN`）違反は `isError: true` を返す。
  - パストラバーサル（`..`・絶対パス・`docs/` 外参照）、既存ファイルへの `scaffold_document`、重複 ID となる `add_block` / `rename_block_id`、および MDX 危険構文（式 `{...}`・ESM・未許可コンポーネント）を含む書き込みは、ファイルを一切変更せず `isError: true` で拒否する。
- **未存在 ID**: `get_document` / `get_relations` / `get_spec_context` / `update_block` / `add_block` / `rename_block_id` に存在しないドキュメント ID またはブロック ID が渡された場合、推測で補完せず `isError: true` で明示エラーを返す。
