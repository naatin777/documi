# CLI コントラクト

`bun src/cli.ts <command>`（または `package.json` の `bin: documi` / `bun run documi:check` / `bun run documi:export`）で実行する。

## パス解決と設定ファイル (`--project` / `--docs` / `.documi.json`・`.documi.yml`)

CLI・HTTP サーバー・stdio MCP はすべて `resolveProjectPaths()` による双方向推論を共有する。

- **既定**: `projectRoot = cwd`、`docsDir = <projectRoot>/docs`（両方省略可）
- **`--project <dir>`（または `DOCUMI_PROJECT_ROOT`）のみ指定**: 指定したプロジェクトルート直下の設定ファイル（あれば）の `docs`、無ければ `<projectRoot>/docs` を自動参照する（MCP 連携では `--project /path/to/repo` の 1 引数だけで完結する）。
- **`--docs <dir>`（または `DOCUMI_DOCS_DIR`）のみ指定**: `projectRoot` は `dirname(docsDir)` を自動推論する。
- **両方指定**: モノレポ等で `docs/` が別階層にある場合に明示上書きできる。
- **設定ファイル（任意）**: プロジェクトルート直下の `.documi.json` → `.documi.yml` → `.documi.yaml` → `documi.json` の順で自動探索し、`docs`（`projectRoot` からの相対パス、既定 `"docs"`）と `testReport`（JUnit XML の相対パス）を読み込む。
- `<SourceRef file="src/..." />`・`<TermDef symbols="src/...#Symbol">`・`@implements` / `@verifies` の走査はすべて解決された `projectRoot` からの相対パスを基準とし、ルート外参照（絶対パス・`..`・外部シンボリックリンク）は拒否される。

## `documi init`

新規プロジェクトに Living Specification 向けの最小 `docs/` 雛形（`goals/project-goal.mdx`, `domain/glossary.mdx`, `decisions/first-decision.mdx`, `specs/example.mdx`）を生成する。既存ファイルは上書きしない。

## `documi serve`

Web UI・Hono RPC REST API・SSE・Streamable HTTP MCP (`/mcp`) を起動し、`docs/` 配下を自動監視する。

| Option | 説明 |
|---|---|
| `--docs <dir>` | 対象 docs ディレクトリ |
| `--project <dir>` | ソースコード参照のプロジェクトルート |
| `--port <number>` | 待ち受けポート（既定: `3000` または `PORT`） |
| `--host <addr>` | バインドアドレス（既定: `127.0.0.1` または `HOST`） |

## `documi mcp`

AI エディタ・CLI エージェント向けに **stdio トランスポート** で MCP サーバーを起動する。HTTP サーバーを常駐させずに全 MCP ツールを利用でき、`fs.watch` により起動中の `docs/` 編集もリアルタイムに反映される。`--project /path/to/repo` を 1 つ渡すだけで設定ファイルまたは `<project>/docs` を自動参照する。

## `documi check`

ドキュメント構造・Rooted DAG・MDX 安全性・AST シンボル・テスト結果・レビュー改ざんを一括検証し、エラーがあれば終了コード `1` を返す。

| Option | 説明 |
|---|---|
| `--docs <dir>` | 対象 docs ディレクトリ（既定: `./docs` または `DOCUMI_DOCS_DIR`） |
| `--project <dir>` | ソース・テスト走査のプロジェクトルート（既定: docs の親または `DOCUMI_PROJECT_ROOT`） |
| `--test-report <xml>` | JUnit XML テストレポートのパス（既定: `docs/.documi/test-results.xml`） |
| `--strict` | 未承認 (`unreviewed` / `stale` / `suspect`) および `drifted` もエラー扱い |
| `--no-review-edit` | Git 作業ツリー上で `docs/.documi/reviews.json` が変更されていたらエラー（AI 改ざん防止） |
| `--prs` | `gh` CLI から PR 情報も取得して紐づけ |
| `--json` | 検証レポートを JSON 形式で出力 |

## `documi approve <block-id...>`

指定した 1 つ以上のセマンティックブロックを承認し、`docs/.documi/reviews.json`（ハッシュ・`approvedCommit`・上流ハッシュ）とローカルキャッシュを更新する。

## `documi export`

複数ドキュメントを `/bundle` × `Bun.WebView` 経由で 1 冊の PDF または単一 HTML にまとめて出力する（事前に `bun run build` が必要）。

| Option | 説明 |
|---|---|
| `--format <pdf\|html>` | 出力形式（既定: `pdf`） |
| `--scope <scope>` | `all` / `dir:<path>` / `goal:<id>`（既定: `all`） |
| `--ids <a,b,c>` | 含めるドキュメント ID をカンマ区切りで明示指定 |
| `--title <text>` | 表紙タイトル |
| `--out <file>` | 出力先ファイルパス（既定: `documi-bundle.pdf` / `.html`） |

## 終了コードと副作用の規約

- **終了コード**: 正常終了は `0`、引数不正・検証エラー（`documi check` 失敗含む）・対象未存在・I/O エラー時は `1` を返す。
- **副作用の範囲**:
  - `documi check` / `documi mcp`: 読み取り専用（ファイル書き換えなし）。
  - `documi init`: 不足している雛形ファイルのみを作成し、既存ファイルは一切上書きしない（冪等）。
  - `documi approve`: `docs/.documi/reviews.json` と `.documi/cache/` のみ更新し、MDX 本文は変更しない。
  - `documi export`: `--out` で指定された出力ファイルのみを書き出す。
