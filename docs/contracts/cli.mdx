# CLI コントラクト

`bun src/cli.ts <command>`（または `package.json` の `bin: documi` / `bun run documi:check` / `bun run documi:export`）で実行する。

## パス解決と設定ファイル (`--project` / `--docs` / `.documi.json`・`.documi.yml`)

CLI・HTTP サーバー・stdio MCP はすべて `resolveProjectPaths()` による双方向推論を共有する。

- **既定**: `projectRoot = cwd`、`docsDir = <projectRoot>/docs`（両方省略可）
- **`--project <dir>`（または `DOCUMI_PROJECT_ROOT`）のみ指定**: 指定したプロジェクトルート直下の設定ファイル（あれば）の `docs`、無ければ `<projectRoot>/docs` を自動参照する（MCP 連携では `--project /path/to/repo` の 1 引数だけで完結する）。
- **`--docs <dir>`（または `DOCUMI_DOCS_DIR`）のみ指定**: `projectRoot` は `dirname(docsDir)` を自動推論する。
- **両方指定**: モノレポ等で `docs/` が別階層にある場合に明示上書きできる。
- **設定ファイル（任意）**: プロジェクトルート直下の `.documi.json` → `.documi.yml` → `.documi.yaml` → `documi.json` の順で自動探索し、`docs`（`projectRoot` からの相対パス、既定 `"docs"`）と `testReport`（JUnit XML の相対パス）を読み込む。
- `<SourceRef file="src/..." />`・`<TermDef symbols="src/...#Symbol">`・`@implements` / `@verifies` の走査はすべて解決された `projectRoot` からの相対パスを基準とし、ルート外参照（絶対パス・`..`・外部シンボリックリンク）は拒否される。

## `documi init`

新規・既存プロジェクト向けに、最小 `docs/` 雛形（`goals/project-goal.mdx`, `domain/glossary.mdx`, `decisions/first-decision.mdx`, `specs/example.mdx`）と **CLI ベースの標準 Agent Skills**（`<project>/.agents/skills/documi/SKILL.md`・`documi-bootstrap/SKILL.md`・`documi-review/SKILL.md`）を生成する。`AGENTS.md` 等の既存ファイルとは競合させず、既存ファイルは `--force-skills` 指定時の `SKILL.md` を除き一切上書きしない。

| Option | 説明 |
|---|---|
| `--en` / `--ja` | 生成する Agent Skills および `docs/` 雛形の言語を指定（既定: `en`、`--lang <en\|ja>` も指定可） |
| `--skills-dir <dir>` | Agent Skills の出力先ディレクトリ（既定: `<project>/.agents/skills`） |
| `--skills-only` | `docs/` 雛形を作らず Agent Skills のみ生成（既存 `docs/` 導入・更新用） |
| `--no-skills` | Agent Skills を生成せず `docs/` 雛形のみ生成 |
| `--force-skills` | 既存の Documi `SKILL.md` を最新版テンプレートで上書き更新 |
| `--json` | 生成結果を JSON 形式で出力 |

## AI・人間向け 読み取り・検索コマンド（すべて `--json` 対応）

MCP サーバーを接続しない環境（CLI + Agent Skills 運用やターミナル直接操作）でも、MCP と同一の Document Core クエリをそのまま利用できる。

| Command | 主な Option | 役割 |
|---|---|---|
| `documi map` | `--json`, `--full` | Goal / Architecture 概要・Decision `<Outcome>`・用語・Review/Realization サマリを一括取得（`--full` で全文展開） |
| `documi list` | `--type <type>`, `--json` | ドキュメント一覧を取得 |
| `documi show <doc-id>` | `--json` | 本文・セマンティックブロック・関係・問題一覧を取得 |
| `documi relations <id>` | `--json` | ドキュメントまたはブロックの外向き・逆参照を取得 |
| `documi search <query...>` | `--type <type>`, `--limit <n>`, `--semantic`/`--no-semantic`, `--provider`, `--model`, `--dtype`, `--endpoint`, `--json` | ドキュメントとセマンティックブロックを BM25＋用語集同義語展開（`--semantic` または `rag.enabled` 時はローカル Embedding＋RRF ハイブリッド）で横断全文検索 |
| `documi retrieve <query...>` | `--type <type>`, `--limit <n>`, `--budget <chars>`, `--no-graph`, `--semantic`/`--no-semantic`, `--provider`, `--model`, `--dtype`, `--endpoint`, `--json` | 自然文から BM25（＋任意でローカル Embedding RRF）＋明示グラフ展開で関連 Spec・上流 Goal・Decision `<Outcome>`・用語・`<SourceRef>` を予算内で 1 発取得 |
| `documi index` | `--provider <onnx\|ollama\|openai>`, `--model <id>`, `--dtype <q4\|q8\|fp16\|fp32>`, `--endpoint <url>`, `--api-key-env <var>`, `--json` | `bun:sqlite` ローカルベクトルキャッシュ（`docs/.documi/cache/embeddings.sqlite`）を `contentHash` 差分で構築・更新 |
| `documi query` | `--kind`, `--intent`, `--stability`, `--review`, `--realization`, `--suspect`/`--no-suspect`, `--has-feedback`/`--no-feedback`, `--q <text>`, `--json`, `--full` | セマンティックブロックを多軸フィルタ検索（既定は軽量サマリ、`--full` で完全展開） |
| `documi context <id>` | `--json`, `--full` | Spec の本文・上流 Goal 概要・未解決フィードバック・関連文書・Decision `<Outcome>`・関連用語・`<SourceRef>` を一括集約（`--full` で完全展開） |

## AI・人間向け 精密編集コマンド（すべて `--json` 対応）

AST 位置ベースで安全に局所編集し、再読込後の検証結果（`validation`）を返却する。`--body -`（または `--definition -`）で標準入力から複数行 Markdown を渡せ、`--body-file <file>` にも対応する。`docs/.documi/reviews.json` への書き込み・パストラバーサル・MDX 危険構文はすべて拒否される。

| Command | 主な Option | 役割 |
|---|---|---|
| `documi block add <doc-id>` | `--kind`, `--id`, `--body`/`--body-file`, `--after-heading`, `--title`, `--stability`, `--intent`, `--derives`, `--supersedes`, `--scope`, `--aliases`, `--symbols`, `--json` | セマンティックブロックを 1 件追記 |
| `documi block update <block-id>` | `--body`/`--body-file`, `--title`, `--stability`, `--intent`, `--derives`, `--supersedes`, `--scope`, `--aliases`, `--symbols`, `--json` | 既存ブロックの該当行範囲のみを安全に更新 |
| `documi block rename <old-id> <new-id>` | `--dry-run`, `--json` | `docs/` とコード・テストのブロック ID 参照を一括リネーム |
| `documi term upsert <term-id>` | `--definition`/`--body`/`--body-file`, `--aliases`, `--symbols`, `--doc`, `--json` | 用語集に `<TermDef>` を追加または更新 |
| `documi scaffold <rel-path>` | `--title`, `--type`, `--description`, `--date`, `--tags`, `--derives`, `--satisfies`, `--verifies`, `--body`/`--body-file`, `--json` | 規約通りの frontmatter を持つ新規 `.mdx` を作成（上書き禁止） |

## `documi serve`

Web UI・Hono RPC REST API・SSE・Streamable HTTP MCP (`/mcp`) を起動し、`docs/` 配下を自動監視する。

| Option | 説明 |
|---|---|
| `--docs <dir>` | 対象 docs ディレクトリ |
| `--project <dir>` | ソースコード参照のプロジェクトルート |
| `--port <number>` | 待ち受けポート（既定: `3000` または `PORT`） |
| `--host <addr>` | バインドアドレス（既定: `127.0.0.1` または `HOST`） |

## `documi mcp`

AI エディタ・CLI エージェント向けに **stdio トランスポート** で MCP サーバーを起動する。HTTP サーバーを常駐させずに全 MCP ツールを利用でき、`fs.watch` により起動中の `docs/` 編集もリアルタイムに反映される。`--project /path/to/repo` を 1 つ渡すだけで設定ファイルまたは `<project>/docs` を自動参照する。

## `documi check`

ドキュメント構造・Rooted DAG・MDX 安全性・AST シンボル・テスト結果・レビュー改ざんを一括検証し、エラーがあれば終了コード `1` を返す。

| Option | 説明 |
|---|---|
| `--docs <dir>` | 対象 docs ディレクトリ（既定: `./docs` または `DOCUMI_DOCS_DIR`） |
| `--project <dir>` | ソース・テスト走査のプロジェクトルート（既定: docs の親または `DOCUMI_PROJECT_ROOT`） |
| `--test-report <xml>` | JUnit XML テストレポートのパス（既定: `docs/.documi/test-results.xml`） |
| `--strict` | 未承認 (`unreviewed` / `stale`) および `drifted` もエラー扱い（`suspect` は参考通知のまま） |
| `--no-review-edit` | Git 作業ツリー上で `docs/.documi/reviews.json` が変更されていたらエラー（AI 改ざん防止） |
| `--prs` | `gh` CLI から PR 情報も取得して紐づけ |
| `--json` | 検証レポートを JSON 形式で出力 |

## `documi approve <block-id...>`

指定した 1 つ以上のセマンティックブロックを承認し、`docs/.documi/reviews.json`（ハッシュ・`approvedCommit`・上流ハッシュ）とローカルキャッシュを更新する。

## `documi unapprove <block-id...>`

指定した 1 つ以上のセマンティックブロックの承認を取り消し、`unreviewed` 状態へ戻す。既存のフィードバックや Stability 上書きは保持し、どちらも無ければレコード自体を削除する。

## `documi export`

複数ドキュメントを `/bundle` × `Bun.WebView` 経由で 1 冊の PDF または単一 HTML にまとめて出力する（事前に `bun run build` が必要）。

| Option | 説明 |
|---|---|
| `--format <pdf\|html>` | 出力形式（既定: `pdf`） |
| `--scope <scope>` | `all` / `dir:<path>` / `goal:<id>`（既定: `all`） |
| `--ids <a,b,c>` | 含めるドキュメント ID をカンマ区切りで明示指定 |
| `--title <text>` | 表紙タイトル |
| `--out <file>` | 出力先ファイルパス（既定: `documi-bundle.pdf` / `.html`） |

## `documi build-site`

Cloudflare Pages / Workers Static Assets・Vercel・Netlify・GitHub Pages・AWS S3 等の任意の静的ホスティングへそのまま配置できる **プロバイダ非依存・読み取り専用の静的 Documi サイト** をオプションで生成する（事前に `bun run build` が必要）。`index.html`（`window.__DOCUMI_STATIC__` 注入済み）・`404.html`・`_headers`（Cloudflare Pages / Netlify 用キャッシュ制御）・`.nojekyll`・`assets/`（CSS フォント URL および動的チャンク preload パスを相対/ベースパス対応化）・`data/*.json`（コードファイルは特殊文字・ドットファイル衝突を避けるためハッシュ索引化）を出力し、フロントエンドは `HashRouter` と静的 JSON フェッチへ自動切替する。

| Option | 説明 |
|---|---|
| `--out <dir>` | 出力先ディレクトリ（既定: `./dist-site`） |
| `--base <path>` | アセット参照のベースパス（既定: `./`） |
| `--no-code` | Code Explorer 用ソース全文および `<SourceRef>` スニペットを含めない |
| `--revisions <n>` | 各ドキュメントで同梱する過去コミット版の最大件数（既定: `5`） |

## 終了コードと副作用の規約

- **終了コード**: 正常終了は `0`、引数不正・検証エラー（`documi check` 失敗含む）・対象未存在・I/O エラー時は `1` を返す。
- **副作用の範囲**:
  - `documi check` / `documi mcp`: 読み取り専用（ファイル書き換えなし）。
  - `documi init`: 不足している雛形ファイルのみを作成し、既存ファイルは一切上書きしない（冪等）。
  - `documi approve` / `documi unapprove`: `docs/.documi/reviews.json` と `.documi/cache/` のみ更新し、MDX 本文は変更しない。
  - `documi export`: `--out` で指定された出力ファイルのみを書き出す。
