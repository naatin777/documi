# バンドル・PDF・静的サイトの検証

## 1. 保証シナリオ（Given / When / Then）

### スコープ別バンドル解決と印刷・バンドル描画

- **Given**: 複数ディレクトリ・`<Tabs>`・`<Details>`・相対リンク・同名見出しを含むドキュメント群がある
- **When**: `all` / `dir` / `goal` / `ids` スコープでバンドルを解決し、バンドルモードで描画する
- **Then**: 指定スコープの文書が順序どおり結合され、内部リンクはページ内アンカー化、見出し ID は文書単位で名前空間化され、`<Tabs>` や `<Details>` は全展開される

### PDF 生成のループバック境界防御

- **Given**: `POST /api/export/pdf` エンドポイントが稼働している
- **When**: 自サーバーのループバック `/bundle` 以外の URL や外部ホストを指定して PDF 生成を要求する
- **Then**: SSRF を防ぐためリクエストは 400/403 で即座に拒否される

### プロバイダ非依存の静的サイト書き出し（`documi build-site`）

- **Given**: ローカルメディアとソースコード参照を含むプロジェクトがある
- **When**: `documi build-site`（および `--no-code` オプション付き）を実行する
- **Then**: `index.html`・`404.html`・`_headers`・`.nojekyll`・事前計算 `data/*.json`・`media/`・相対パス書き換え済みアセットが出力され、`--no-code` 指定時はソースコード索引が出力されない

## 2. 対応テストスイート

| テストスイート | 主な検証対象 |
|---|---|
| `tests/bundle.test.tsx` | バンドル解決（`all` / `dir` / `goal` / `ids`）・バンドルモード描画（ページ内アンカー化・見出し ID 名前空間化・全タブ展開）・`/api/bundle` |
| `tests/site.test.ts` | `documi build-site` 静的書き出し・全読み取り JSON 事前計算・コードファイルハッシュ索引・CSS/preload 相対パス書き換え・`--no-code`・`_headers` / `.nojekyll` / `404.html` |
| `tests/api.test.ts`（PDF セクション） | `POST /api/export/pdf` の入力検証および自サーバーのループバック `/bundle` 以外を拒否する SSRF 防御 |
