# Core・Reviews・Trace・Bundle・API・MCP・UI の検証方針

## 1. テスト戦略と証拠主義（Prove It Works）

- **ビルド通過や自己申告を完了とみなさない**: 仕様・契約・修正の完了は、実際の自動テスト実行結果（JUnit XML）および静的・構造チェックの通過という客観的証拠で証明する。
- **形骸テストと過剰モックの禁止**: 定数を写しただけの落ちないテストや、内部実装を過剰モックしたテストは避け、実際のファイルシステム（一時ディレクトリ）・Hono アプリ・`bun:sqlite`・mdast / `@ast-grep/napi`・MCP ツールを通して振る舞いを検証する。
- **バグ修正は Red → Green で確認**: 不具合修正時は、修正前の状態で失敗する再現テストを先に確認してから修正を通す。
- **重要領域の強化検証**: MDX 安全性（任意 JS・未許可構文拒否）、`projectRoot` パストラバーサル・シンボリックリンク防御、Rooted DAG 循環・孤立検出、サイドカー承認と `stale`/`suspect` 遷移、設定ファイル厳格検証、静的書き出しのパス安全性・`--no-code` 遮断、RAG 障害時の BM25 フォールバックは境界値・異常系を必須で検証する。

## 2. 品質ゲート（マージ前必須コマンド）

PR および変更完了時は、以下をすべてエラー・警告 0 件で通過させる。

```bash
bun test --reporter=junit --reporter-outfile=docs/.documi/test-results.xml
bun run check
bun run lint
bun run format:check
bun run knip
bun run build
bun run documi:check
```

## 4. 意図的な対象外（Out of Scope）

以下は CI 自動テストの既定対象外とし、過剰なテスト維持コストや環境依存フレーキーを避ける：

- ヘッドレスブラウザによるピクセル単位のビジュアル回帰テスト（WebGL グラフ描画・PDF レイアウト・静的サイト配信の目視確認はローカルスモーク検証で行う）
- 外部 GitHub API (`gh pr list`) や外部 Embedding API（Hugging Face モデル初回ダウンロード・実 Ollama / OpenAI サーバー）への実ネットワーク通信を伴う CI 結合テスト（CI では決定論的モックプロバイダで検証し、実 ONNX モデル `embeddinggemma-300m-ONNX` による推論・キャッシュ確認はローカルスモークで行う）
