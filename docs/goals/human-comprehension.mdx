# 人間が読んでシステムとコードまで深く理解できる

## 誰の課題か（Target Actors）

- AI と協働してプロダクトを育てる開発者・テックリード
- プロジェクトに途中参加し、仕様とソースコードの対応を短時間で把握したいメンバー
- 仕様書を 1 冊の資料としてオフライン・外部レビューで読みたい関係者

## いま何が困っているのか（Problem Statement）

1. **AI がコードや文書を大量生成するほど、人間の理解が追いつかない**: 長大な Markdown や散らばった作業ログを渡されても、「何が確定仕様で、どの設計と繋がり、どのコードが実体なのか」を追いきれない。
2. **ドキュメントとソースコードが別世界に分断されている**: 用語の意味を文章で読んでも、実際のソースコード上のどの型・関数がそれに対応するのかを毎回 grep で探す手間がかかる。
3. **複数文書をまたいだ全体像や関係が見えにくい**: 仕様書と設計書や ADR を見比べたいときにタブを行き来して見失い、プロジェクトが大きくなると文書同士の依存関係も頭に入らなくなる。
4. **外部共有や通読のためにまとめる手段がない**: 個別の Markdown ファイルは Git 上にあっても、Goal や機能単位で 1 冊の仕様書として通読・印刷・PDF 共有するのが面倒。

## どうなってほしいか（Desired Outcome）

- 人間が Web UI を開いて上から下へ（`Goals → Architecture → Domain → Specs → Contracts → Designs → Decisions → Verification → Guides`）読むだけで、**プロジェクトの目的から設計・テストまでが物語として頭に入る**。
- 本文中の用語や `<SourceRef>` から **実ソースコードの最新の型・関数定義をその場で確認** でき、ドキュメントがそのまま「ソースコード理解の地図」として機能する。
- 関連する仕様書・設計書・ADR を **並べて読み比べ（Side-by-Side プレビュー）**、ネットワークグラフ上で **ノードをクリックしながら中身をサクッと探索** できる。
- 必要な範囲（全体・ディレクトリ・Goal 関連一式・任意選択）を **表紙・目次付きの 1 冊の HTML / PDF として即座に書き出せる**。

## 成功のサイン（Success Signals）

- 初めてリポジトリに触れる人間でも、コードを隅々まで grep する前に `docs/` の閲覧と用語ホバー・グラフ探索だけで主要コンポーネントと設計意図を説明できる。
- レビュー時に「この仕様に対応する設計書と ADR はどれか」を 1 クリックで並べて確認できる。
