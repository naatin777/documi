# 目的

ソフトウェア開発では、仕様・設計・意思決定・検証の記録が散在しがちである。
「なぜこの設計にしたのか」「この要件はどこで検証されたのか」を後から追跡できないことが、手戻りや認識齟齬の原因になる。

Documi は、これらの文書を Artifact として構造的に管理し、文書間の関係を辿れるようにすることで、ドキュメント中心の開発を支える。

## 達成したい状態

- 要件から設計・実装・検証までの流れを文書間リンクで追跡できる
- 文書の承認状態（draft / accepted / deprecated）が一目で分かる
- 人間だけでなく AI エージェントも文書とその関係を機械的に参照できる
- ファイルシステム上の Markdown / MDX を Single Source of Truth として扱える
