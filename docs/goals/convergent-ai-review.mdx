# docs を正とした AI レビューが有限回で収束する

## 誰の課題か（Target Actors）

- AI エージェントにコードレビューを依頼し、一定の品質ラインで確実にマージ判断を下したい開発者・テックリード
- 複数の AI モデルや複数セッションを跨いでコードを検査・検証する AI エージェント

## いま何が困っているのか（Problem Statement）

1. **AI にコードレビューを頼むと、修正案が無限に出てキリがない**: 「何をもって OK とするか」の判定基準（停止条件）がないため、修正を反映して再レビューさせるたびに、好みの範囲のリファクタ案や念のための防御コードが際限なく増え続ける。
2. **既決事項やスコープ外を何度も蒸し返される**: 別の AI セッションや別モデルが過去の合意を知らないまま、「意図的にやらないこと（Non-Goals）」への対応提案や、すでに採否を決めた設計トレードオフのやり直しを毎回指摘してくる。
3. **`docs/` 自体が曖昧だと、いつまでもレビューが収束しない**: 仕様の境界条件・エラー時の振る舞い・責務の線引きが `docs/` に書き切れていないと、AI ごとに異なる解釈が生まれ、同じ箇所に対して堂々巡りの指摘が止まらなくなる。
4. **「これ以上直さなくてよい」と自信を持って言えない**: レビューが終わる条件が主観的なため、人間が途中で打ち切るしかなく、見落としへの不安や過剰な修正コストが残る。

## どうなってほしいか（Desired Outcome）

- **`docs/` を唯一の判定基準（Oracle / 停止条件）としてコードレビューが機能する**: `<Spec>`・`contract`・`<Constraint>`・`Non-Goals`・`decision` の `<Outcome>` を正とすることで、「仕様・契約・制約からの逸脱」だけが要修正として報告され、スコープ外提案や既決事項の蒸し返しが起きない。
- **どの AI にレビューさせても有限回で収束する**: 逸脱を直したあとは、別のセッションや別モデルの AI にレビューさせても「`docs/` に照らして重大な指摘はもうありません」とほぼ同じ結論へ収束する。
- **収束しない指摘を「`docs/` の曖昧さ」としてあぶり出し、潰せる**: レビュー中に解釈の揺れや未定義ケースが見つかったときは、コード上で延々と議論せず **`docs/` 側へ確定事項（`<Spec>` / `Non-Goals` / `<Constraint>` / `ADR <Outcome>`）として書き戻す** ことで、二度と同じ指摘が再発しない循環が回る。
- **最初から曖昧さが入りにくい執筆・検証の仕組みがある**: 各 Artifact Type の役割・粒度ルールや構造チェックにより、「レビューが発散する原因になる曖昧な仕様」を事前に減らせる。

## 成功のサイン（Success Signals）

- `docs/` を参照した AI コードレビューで、仕様違反・契約違反を修正した後に再レビュー（別セッション・別モデル含む）を行っても、新たな重大指摘が出ず有限回（目安 1〜2 ラウンド）で収束する。
- レビューで発散・反復する論点が出たとき、「コードのバグ」なのか「`docs/` の曖昧さ・未定義」なのかを切り分け、`docs/` を 1 回更新すれば以降のセッションで同じ蒸し返しが再発しなくなる。
