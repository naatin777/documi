# 人間の手作業を最小化しつつ、脱線と乖離を構造で防ぐ

## 誰の課題か（Target Actors）

- AI に大部分の執筆・実装を任せつつ、品質と方向性の責任を持つ開発者・レビューア
- 継続的インテグレーション（CI）上で仕様とコードの整合性を担保したいチーム

## いま何が困っているのか（Problem Statement）

1. **「仕様に書いてあるから実装済みだと思っていた」事故が起きる**: 単一の `status: draft | accepted` だけでは「人間が承認したか」と「実際に実装されテストが通っているか」が混線し、手動チェックリスト (`tasks.md`) もすぐ陳腐化する。
2. **AI が良かれと思って勝手に仕様を生やし、目的から脱線する**: 上流の Goal と無関係な機能仕様がいつの間にか増え、人間が気づきにくい。
3. **AI のファイル直書きと人間承認の信頼性が両立しない**: MDX 本文に承認フラグやハッシュを埋め込むと、AI が編集時に誤って承認を書き換えるリスクがあり、Git diff も汚れる。一方で Web UI で本文編集を強制すると効率が落ちる。
4. **仕様変更・コード変更に伴う波及やリンク切れを見落とす**: 上流仕様が変わったのに下流設計が古いままだったり、リファクタでコードシンボル名が変わってドキュメントの参照が壊れても気づけない。

## どうなってほしいか（Desired Outcome）

- **人間の作業は「確認・ワンクリック承認・一言フィードバック・PR マージ」だけ** に最小化され、執筆・タグ付け・検証・進捗更新の雑務から解放される。
- 承認記録は MDX 本文から物理分離されたサイドカー（`reviews.json`）で保護され、**承認後に本文が変われば自動で `stale`＋行 diff 表示、上流が変われば下流に `suspect` が自動波及** する。
- 仕様の実現状態（`realization`）は手書きを禁止し、**ソースコード・テスト・JUnit 実行結果・PR から完全自動で算出** される。
- `normative` な仕様の Goal 到達性（Rooted DAG）・AST シンボル実在性・MDX 安全性・`reviews.json` 改ざん禁止が **CLI / CI / MCP で自動検証** され、脱線や壊れた参照がマージ前に確実に止まる。

## 成功のサイン（Success Signals）

- 人間が `/review`（Review Queue）を開くだけで、AI が新規追加・変更した仕様と承認時点からの行差分を即座に把握して承認・フィードバックできる。
- テストが 1 件でも落ちたり `<SourceRef>` のシンボルが消えたりすれば、手動点検なしで `drifted` や `documi check` エラーとして自動検知される。
