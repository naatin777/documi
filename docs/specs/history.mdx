# Git 鮮度・変更ブロック検出仕様

## 1. 読み取り専用 Git 鮮度・変更ブロック抽出

<Spec id="core.doc-history" stability="evolving" derives="goals/human-comprehension">
  **When** Document Core が `docs/` を読み込むとき、
  **the** Document Core **shall** 読み取り専用の Git 連携（非 Git 環境ではファイル時刻へのフォールバック）により各文書の作成日時・最終更新日時・未コミット変更状態を算出し、変更行が重なるブロック ID を抽出できるようにする。Git リポジトリへの書き込み操作は一切行わない。
</Spec>

- **鮮度算出の優先順位**:
  1. Git リポジトリ内: 単一 `git log --name-status -M`（リネーム追跡込み）と `git status --porcelain -uall` で全文書の `createdAt`・`updatedAt`・`lastCommitSha`・`lastCommitSubject`・`commitCount`・`workingStatus`（`modified` / `added` / `untracked`）を一括付与する。未コミット変更がある場合は `updatedAt` に FS `mtime` を反映する。
  2. 非 Git 環境: FS の `birthtime` / `mtime` へ安全にフォールバックし、`gitAvailable: false` を返す。
- **Git 変更ブロック抽出 (`getChangedBlockIds`)**:
  - `main` / `master` 以外のブランチ上では `origin/main` → `main` → `origin/master` → `master` の順で `merge-base` を探索し、`git diff -U0 <base>` と作業ツリー新規ファイル（`untracked` / `added`）を統合して変更行が重なるブロック ID のみを抽出する。drift 検知の入力として使われる。

## 保証シナリオ

<Test id="test.history" verifies="core.doc-history" level="integration">
  - **Given**: 複数コミット履歴を持つドキュメント
  - **When**: 鮮度算出と変更ブロック抽出を行う
  - **Then**: 作成日時・最終更新・未コミット状態が付与され、非 Git 環境でも安全にフォールバックする
</Test>
