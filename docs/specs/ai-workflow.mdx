# プロジェクト設定・Agent Skills・AI CLI・MCP 精密編集仕様

## 1. プロジェクト設定ファイルと双方向パス解決

<Spec id="core.project-config" stability="evolving" derives="goals/low-friction-governance">
  **When** CLI・HTTP サーバー・MCP サーバーが `projectRoot`・ドキュメントマウント（`docs`）・テストレポート（`testReport`）を解決するとき、
  **the** Document Core **shall** 既定を `<projectRoot>/docs` としつつプロジェクトルート直下の設定ファイル（`.documi.json` / `.documi.yml` / `.documi.yaml` / `documi.json`）から単一または複数マウント配列の `docs`（`string | { id?, path, label? }[]`）および単一／複数配列の `testReport`（`string | string[]`）を自動読み込みし、`--project` / `--docs` の双方向推論と `--mount <id>` によるマウント絞り込みを提供する。不正な構文・未定義キー・重複マウント ID は `ConfigError` として拒否する。
</Spec>

- **優先順位**: CLI 引数（`--project` / `--docs` / `--test-report`）＞ 環境変数（`DOCUMI_PROJECT_ROOT` / `DOCUMI_DOCS_DIR`）＞ プロジェクト設定ファイル（`.documi.json` → `.documi.yml` → `.documi.yaml` → `documi.json`）＞ 既定値（`projectRoot = cwd`, `docsDir = <projectRoot>/docs`）。
- **複数 `docs` マウントと名前空間**:
  - `docs` が文字列（または省略）のときは単一 `root` マウント（プレフィックスなし）として扱う。
  - `docs` が配列 `{ id?: string, path: string, label?: string }[]` のとき、`id` 省略または `"root"` のマウントは Document ID にプレフィックスを付けず、名前付きマウント（例: `id: "web"`, `path: "apps/web/docs"`）は Document ID に `<id>/...` を付与する。
  - 各マウントの `guard/reviews.json` はパッケージ単位で分散配置し、読み込み時に統合・承認書込時は所属マウントへ保存する（`--no-review-edit` は全マウントの `guard/reviews.json` を検査）。
  - `--mount <id>` は **全体グラフをロードした上で** 対象マウントの文書・ブロック・検証結果へ絞り込む（別マウントの `goal` や `contract` への参照が偽陽性で壊れない）。`documi scaffold` は `--mount` 省略時はプライマリ（`root` または先頭マウント）へ出力する。
- **複数 `testReport`（JUnit XML）**: `testReport` に配列を指定した場合、全 JUnit XML のテスト結果を統合して各 `<Spec>` の `realization` を算出する。
- **双方向推論マトリクス**:
  - 両方省略: `projectRoot = cwd`、設定の `docs`（既定 `"docs"`）を結合
  - `--project` のみ: 指定ルート直下の設定を読み、マウント群を解決
  - `--docs` のみ: `projectRoot = dirname(docsDir)` を逆算して設定を読み込む（明示 `--docs` が単一マウントとして優先）
  - 両方指定: モノレポ等で明示上書きを許可
- **厳格拒否**: JSON/YAML 構文エラー・スキーマ型違反・未知キー（タイポ含む）・マウント ID 重複や不正形式は即座に `ConfigError` を送出する（スキーマは [永続ファイル契約](../contracts/storage-formats.mdx)）。

## 2. Agent Skills 配布と Brownfield 導入初期化

<Spec id="core.agent-skills-init" stability="evolving" derives="goals/ai-reproducibility">
  **When** `documi init` が実行されたとき、
  **the** Document Core および CLI **shall** 既存の `AGENTS.md` 等と競合させずに標準 Agent Skills 形式（既定 `<projectRoot>/.agents/skills/`）で CLI ベースの 4 スキル（日常運用 `documi/SKILL.md`・既存コードベース導入 `documi-bootstrap/SKILL.md`・対話型仕様レビュークイズ `documi-review/SKILL.md`・再現性監査＆肉付け `documi-audit/SKILL.md`）と `docs/` 雛形を指定言語（`--en` / `--ja` / `--lang`、既定 `en`）で冪等に生成する。既存ファイルは明示フラグ（`--force-skills`）なしに上書きしない。
</Spec>

- **生成ファイル（冪等・非破壊）**:
  - `docs/` 雛形 4 件: `goals/project-goal.mdx`, `domain/glossary.mdx`, `decisions/first-decision.mdx`, `specs/example.mdx`（生成直後に `documi check` がエラー 0 件で通過する完全な Rooted DAG を構成）
  - `.agents/skills/` 4 件: `documi/SKILL.md`, `documi-bootstrap/SKILL.md`, `documi-review/SKILL.md`, `documi-audit/SKILL.md`（すべて CLI ベースで MCP ツール名と重複しない）
  - `documi/SKILL.md` は **Spec-First 運用・Capability 単位分割・矛盾防止・合意の即時永続化・視覚ファースト執筆規約**（変更前に `documi impact` で影響範囲を棚卸し → `docs/` を実装より先に更新し 1 事実 1 箇所・1 Capability 1 ファイル・方針転換時は `supersedes` を付与 → 逆ピラミッド・1 段落 3 行以内・箇条書き先頭太字・流れは Mermaid・分岐は表・補足は `<Details>`・比較は `<Columns>`・時系列は `<Timeline>` でスキャンしやすく記述 → チャット合意は `<Outcome>` / `<Spec>` / `<Constraint>` / `<Note intent="idea">` へ即記録 → `documi check` → コード実装）を標準手順として内蔵する。
  - `documi-audit/SKILL.md` はコードとの整合監査に加え、**実装前の `docs/` 同士の意味的矛盾チェック**（変更文書と `documi impact` 先のクロスチェック）および **長文散文の図表・`<Details>` 化ダイエット監査** も扱う。
- **境界条件**: 既存 `AGENTS.md` / `CLAUDE.md` は作成・変更しない。`--en` と `--ja` の同時指定や不正 `--lang` は引数エラーで終了コード `1`。`--skills-only` は雛形をスキップ、`--no-skills` はスキルをスキップ、`--force-skills` のみ既存 `SKILL.md` を上書き更新する。

## 3. AI・人間向け CLI クエリ・変更影響分析・精密編集と MCP 自己完結

<Spec id="core.ai-cli" stability="evolving" derives="goals/ai-reproducibility">
  **When** AI エージェントまたは人間が CLI 経由でプロジェクトマップ・文書検索・Spec 文脈取得・ブロック精密編集を実行するとき、あるいは MCP クライアントが `documi mcp` / `/mcp` に接続するとき、
  **the** Documi CLI および MCP Server **shall** 共通の Document Core を介して CLI 経路（`map` / `list` / `show` / `relations` / `impact` / `search`［`--context` グラフ展開対応］ / `index` / `query` / `context` / `block` / `term` / `scaffold`、`--json`・コマンド別フラグ検証・`check --format github` 対応）と MCP 経路（`McpServer` の `instructions` 内蔵・14 ツール）の双方を互いに依存せず自己完結して提供する。
</Spec>

- **既定コンパクト＋段階開示**: `map` / `query` / `context` は既定で必要最小限の要約・行範囲のみを返し、`--full` / `full: true` 時のみ全文・全トレース配列・全 `<SourceRef>` の公開シンボルを展開する。
- **変更影響分析 (`documi impact <id>` / MCP `get_impact`)**: 指定したドキュメント ID またはブロック ID を起点に、下流の `derives` / `satisfies` / `verifies` / `supersedes` / `mentions` エッジを再帰走査（既定最大深度 `4`、循環安全）し、影響を受けるドキュメント一覧・ブロック一覧（距離 `depth` と経由エッジ種別付き）・関連 `<SourceRef>` および実装／テスト参照を一覧化する。仕様変更前の矛盾防止・更新漏れ防止に用いる。
- **複数行入力の安全性**: CLI の `block add` / `block update` / `term upsert` / `scaffold` は `--body -`（標準入力ヒアドキュメント）と `--body-file <file>` をサポートし、バッククォートや改行のシェル崩れを防ぐ。

## 4. コンテキスト最小化のための MCP / CLI 精密編集

<Spec id="core.mcp-surgical-edit" stability="evolving" derives="goals/ai-reproducibility">
  **When** AI エージェントが MCP 経由で特定のセマンティックブロック・用語・新規文書雛形・ブロック ID リネームを操作するとき、
  **the** Document Core および MCP Server **shall** 読み取りツールで各ブロックの正確な `docPath`・`startLine`・`endLine` を提供するとともに、対象ブロックや対象ファイルのみを AST 位置ベースで安全に書き換えて即時再読込と検証結果を返す。`docs/` 外への脱出、MDX 危険構文（式・ESM・未許可コンポーネント）、ID 重複、および `docs/guard/`・`.documi/`・`reviews.json` への書き込みは一切拒否する。
</Spec>

- **事前検証と拒否条件（ファイルを 1 バイトも書き換えず拒否）**:
  - 絶対パス、`..` 含む相対パス、`docs/` 外へのシンボリックリンク脱出
  - `guard/` 配下・`.documi/` 配下・`reviews.json` への書き込み
  - `.mdx` / `.md` 以外の拡張子
  - `scaffold` 時の既存ファイル上書き
  - `BLOCK_ID_PATTERN` 違反・既存ブロック ID との重複
  - 本文中の MDX 危険構文（`import`/`export`・JSX 式 `{...}`・スプレッド属性・未許可コンポーネント）
- **`rename_block_id` の置換範囲**: 全 `docs/` のブロック定義・frontmatter/属性の `derives`/`satisfies`/`verifies`/`supersedes`・`<SourceRef>` および `projectRoot` 配下の `@implements`/`@verifies`/`test("[id]")` を対象とし、`dryRun: true` / `--dry-run` で変更予定一覧のみ確認できる。
