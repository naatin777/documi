# ドキュメントモデル・レビュー・トレース・バンドル仕様

## ファイル構造と識別

<Spec id="core.document-model" stability="stable" derives="goals/ai-reproducibility">
  **When** Documi が `docs/` ディレクトリを読み込むとき、
  **the** Document Core **shall** 任意階層の `.mdx` / `.md` ファイルを連番なしで再帰走査し、拡張子を除いた POSIX 相対パスをドキュメント ID として割り当てるとともに、任意の `date`（`YYYY-MM-DD` / `YYYY-MM`）メタデータを解析して `decision` 文書を新しい決定日順に整列する。
</Spec>

<Spec id="core.type-inference" stability="stable" derives="goals/low-friction-governance">
  **When** ドキュメントの frontmatter に `type` が省略されたとき、
  **the** Document Core **shall** 最上位ディレクトリ名 → ファイル名の順に 9 種類の Artifact Type を自動推論し、判別できない場合は警告を記録しつつ `guide` として読み込む。
</Spec>

## セマンティックブロックと安全解析

<Spec id="core.mdx-blocks" stability="stable" derives="goals/ai-reproducibility">
  **When** MDX 本文に `<Spec>` / `<Constraint>` / `<Outcome>` / `<Note>` / `<TermDef>` が記述されているとき、
  **the** Document Core **shall** mdast からブロック構造と正規化 SHA-256 `contentHash` を抽出し、プロジェクト全体でのブロック ID 重複を検出する。
</Spec>

<Spec id="core.mdx-safety" stability="stable" derives="goals/low-friction-governance">
  **If** MDX 本文に ESM import/export・JSX 式 `{...}`・スプレッド属性・未許可コンポーネントが含まれる場合、
  **then the** Document Core **shall** コードを実行せず `mdx-unsupported` 問題として報告する。
</Spec>

## Rooted DAG と脱線防止

<Spec id="core.rooted-dag" stability="stable" derives="goals/low-friction-governance">
  **When** `intent="normative"` の `<Spec>`（または `<Spec>` を持たない `spec` 文書）が存在するとき、
  **the** Document Core **shall** `derives` 辺を辿って 1 つ以上の `goal` に到達できることを検証し、到達できない場合は `orphan-spec` として報告する。`intent="idea"` のブロックは対象外とする。
</Spec>

<Spec id="core.auto-mentions" stability="stable" derives="goals/human-comprehension">
  **When** 本文中に他ドキュメントへの相対 Markdown リンクまたは `<Term>` 参照が存在するとき、
  **the** Document Core **shall** `mentions` エッジを自動構築し、参照先と逆参照 (`incoming`) の双方に反映する。
</Spec>

## 人間レビュー・Diff・Suspect Links

<Spec id="core.human-review" stability="stable" derives="goals/low-friction-governance">
  **When** 人間がセマンティックブロックを承認したとき、
  **the** Document Core **shall** MDX 本文ではなくサイドカー `docs/.documi/reviews.json` にコンテンツハッシュ・承認コミット SHA・上流ハッシュを保存し、本文変更で `stale`、上流変更で `suspect` を自動判定するとともに承認時点からの行 diff を算出する。
</Spec>

## コード・テスト・PR 連携と実装状態の自動算出

<Spec id="core.realization" stability="stable" derives="goals/low-friction-governance">
  **When** プロジェクトのソース/テスト・JUnit XML レポート・PR 情報を走査するとき、
  **the** Document Core **shall** `@implements` / `@verifies` / `test("[id] ...")` / `<SourceRef>` / PR 参照を集約し、各 `normative` `<Spec>` の `realization` (`unimplemented` / `in-progress` / `implemented` / `verified` / `drifted`) を完全自動で算出する。
</Spec>

<Spec id="core.ast-check" stability="stable" derives="goals/low-friction-governance">
  **When** `documi check` または MCP `validate_docs` が実行されたとき、
  **the** Document Core **shall** 全 `<SourceRef>` および `<TermDef symbols="...">` を `@ast-grep/napi` で実在検証し、`--no-review-edit` 指定時は `reviews.json` の未許可変更もエラーとして検出する。
</Spec>

## 複数バンドル解決と全文検索

<Spec id="core.bundle-export" stability="evolving" derives="goals/human-comprehension">
  **When** `all` / `dir:<path>` / `goal:<id>` / 明示 `ids` のいずれかでバンドルが要求されたとき、
  **the** Document Core **shall** 対象ドキュメント一式（Goal 起点時はトレーサビリティ下流および関連用語集・Decision を自動同梱）を解決する。
</Spec>

<Spec id="core.full-text-search" stability="evolving" derives="goals/human-comprehension">
  **When** 検索クエリが与えられたとき、
  **the** Document Core **shall** ドキュメントのタイトル・ID・タグ・本文および全セマンティックブロックを横断してスコアリング検索し、スニペット付きで返却する。
</Spec>

## コンテキスト最小化のための MCP 精密編集

<Spec id="core.mcp-surgical-edit" stability="evolving" derives="goals/ai-reproducibility">
  **When** AI エージェントが MCP 経由で特定のセマンティックブロック・用語・新規文書雛形・ブロック ID リネームを操作するとき、
  **the** Document Core および MCP Server **shall** 読み取りツールで各ブロックの正確な `docPath`・`startLine`・`endLine` を提供するとともに、対象ブロックや対象ファイルのみを AST 位置ベースで安全に書き換えて即時再読込と検証結果を返す。`docs/` 外への脱出、MDX 危険構文（式・ESM・未許可コンポーネント）、ID 重複、および `docs/.documi/reviews.json` への書き込みは一切拒否する。
</Spec>

## ドキュメント鮮度・最新変更箇所・過去版参照

<Spec id="core.doc-history" stability="evolving" derives="goals/human-comprehension">
  **When** Document Core が `docs/` を読み込むか、指定ドキュメントの履歴・過去バージョンを要求されたとき、
  **the** Document Core **shall** 読み取り専用の Git 連携（非 Git 環境ではファイル時刻へのフォールバック）により各文書の作成日時・最終更新日時・未コミット変更状態・コミット履歴・最新変更の本文基準行レンジを算出し、検証済みのコミット SHA に対して過去バージョンの文書本文を安全に返却する。Git リポジトリへの書き込み操作は一切行わない。
</Spec>

## プロジェクト設定ファイルと双方向パス解決

<Spec id="core.project-config" stability="evolving" derives="goals/low-friction-governance">
  **When** CLI・HTTP サーバー・MCP サーバーが `projectRoot` と `docsDir` を解決するとき、
  **the** Document Core **shall** 既定を `<projectRoot>/docs` としつつプロジェクトルート直下の設定ファイル（`.documi.json` / `.documi.yml` / `.documi.yaml` / `documi.json`）から `docs` と `testReport` を自動読み込みし、`--project` のみ指定時は `<projectRoot>/<docs>` を、`--docs` のみ指定時はその親ディレクトリを `projectRoot` として双方向に自動解決する。不正な構文や未定義キーは `ConfigError` として拒否する。
</Spec>

## Agent Skills 配布と Brownfield 導入初期化

<Spec id="core.agent-skills-init" stability="evolving" derives="goals/ai-reproducibility">
  **When** `documi init` が実行されたとき、
  **the** Document Core および CLI **shall** 既存の `AGENTS.md` 等と競合させずに標準 Agent Skills 形式（既定 `<projectRoot>/.agents/skills/`）で CLI ベースの日常運用スキル（`documi/SKILL.md`）および既存コードベース導入スキル（`documi-bootstrap/SKILL.md`）と `docs/` 雛形を指定言語（`--en` / `--ja` / `--lang`、既定 `en`）で冪等に生成する。既存ファイルは明示フラグ（`--force-skills`）なしに上書きしない。
</Spec>

## AI・人間向け CLI クエリ・精密編集と MCP 自己完結

<Spec id="core.ai-cli" stability="evolving" derives="goals/ai-reproducibility">
  **When** AI エージェントまたは人間が CLI 経由でプロジェクトマップ・文書検索・Spec 文脈取得・ブロック精密編集を実行するとき、あるいは MCP クライアントが `documi mcp` / `/mcp` に接続するとき、
  **the** Documi CLI および MCP Server **shall** 共通の Document Core を介して CLI 経路（`map` / `list` / `show` / `relations` / `search` / `query` / `context` / `block` / `term` / `scaffold`、`--json` 対応）と MCP 経路（`McpServer` の `instructions` 内蔵）の双方を互いに依存せず自己完結して提供する。
</Spec>

## 静的サイト書き出し（オプション・プロバイダ非依存）

<Spec id="core.static-site" stability="evolving" derives="goals/human-comprehension">
  **When** `documi build-site` が実行されたとき、
  **the** Documi CLI および Web UI **shall** ビルド済み Web UI アセット（CSS フォント URL・動的チャンク preload ベースパス・favicon を含む相対/任意ベースパス対応済み）と事前計算済みの全読み取り API JSON（Overview・ツリー・ドキュメント詳細・履歴・過去版・グラフ・マトリクス・検索インデックス・任意でハッシュ索引化したコード＆`<SourceRef>` スニペット・アイコン）およびホスティング補助ファイル（`_headers`・`.nojekyll`・`404.html`・`window.__DOCUMI_STATIC__` 注入済み `index.html`）を静的ディレクトリへ出力し、Cloudflare Pages / Workers Static Assets・Vercel・Netlify・GitHub Pages・S3 等の任意の静的ホスティング上でサーバーレス・読み取り専用に動作できるようにする。`--no-code` 指定時はソースコード全文を含めない。
</Spec>
