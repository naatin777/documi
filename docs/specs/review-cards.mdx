# Review Card プロトタイプ仕様

<Spec id="ui.review-cards-prototype" stability="volatile" derives="goals/human-comprehension">
  **When** ユーザーが `/cards` を開いたとき、
    **the** Web UI **shall** 再設計会話から抽出した 5〜8 件の <Term name="ReviewCard" /> を縦に並べて表示し、各カードには問い・状況となぜ今か・何もしないとどうなるか（AI がどう仮置きして進めるか、または進められないか）・具体例・選択肢の箱（名前と一言・得るもの・失うもの）のみを判断材料として表示する。人間が問を見て自力で判断できるメタ情報（種別・重要度・仮置き可否のチップ、不確かさ一覧、並び順の根拠、証拠）や、選択肢間で差が出にくい補助軸の一律表示（影響・可逆性の欄）はカードに表示しない。可逆性などの実質的なコストは失うものの記述に折り畳む。アンカリングを避けるため AI の評価を先見せせず、独立した AI 推奨セクションも表示しない。カードの文章はすべて、会話の文脈やその場で生まれた造語・英語混じりの略語に依存せず、読み手がカード単体で理解できる平易な言葉で書く。各カードの選択肢には、その問いに固有の文言と具体的な得るもの/失うものを持つ「やらない」選択肢を1つ含め、定型文の機械的な自動付与はしない。選択肢リストの末尾には「他のやり方がある」書き込み選択肢を選択肢と同じ体裁で表示し、人間が自分の選択肢を一行で書き込み、他の選択肢と同様に選んで仮置き・確定できるようにする。書き込まれた内容にAIの書き起こしや承認は要求せず、内容が不明な場合は既存のチャット修理経路で確認する。
</Spec>


<Spec id="ui.review-card-actions" stability="volatile" derives="goals/human-comprehension">
  **When** ユーザーが <Term name="ReviewCard" /> を操作したとき、
  **the** Web UI **shall** 選択肢の箱をクリックする選択を入力として受け付け、カードの状態を「開いている」「仮置き」「確定」のいずれかに遷移させる。アクションは「意味がわからない」「納得いかない」「仮置き」「確定」の4つとし、「仮置き」「確定」は選択肢が選ばれるまで無効とし、「仮置き」ボタンは仮置きできると判定されたカードにのみ表示する（仮置きできないカードでは非表示とし、無効表示もしない）。選んだ選択肢は押したボタンの強度で適用され、仮置きは人間が選んだ方向の仮適用を意味する。「意味がわからない」はカードを破損状態（決定も仮置きもできない）にし、破損時に既存の回答は無効として取り消される、「納得いかない」は進行を妨げない異議フラグとする。決められていないカードは操作なしに開いたまま残り、操作結果はカードストアに永続化される。
</Spec>


<Test id="test.ui.review-cards-prototype" level="integration" verifies="ui.review-cards-prototype, ui.review-card-actions">
  - **Given**: 再設計会話由来の固定 Review Card データを持つ Web UI
    - **When**: `/cards` を描画し、選択肢の選択・仮置き/確定の仕上げ・意味がわからない/納得いかないの信号を行う
    - **Then**: 問い・状況となぜ今か・何もしないとどうなるか・具体例・選択肢の得るもの/失うものが表示され、種別・重要度・不確かさ一覧・並び順の根拠・証拠・独立した AI 推奨セクションは表示されず、仮置き/確定は未選択では無効、仮置きボタンは仮置きできないカードでは表示されず、選択とボタンで状態が「仮置き」「確定」に遷移し、操作はカードストアに永続化され、再読み込み後も回答状態が復元される
</Test>

<Spec id="core.review-card-store" stability="volatile" derives="goals/living-specification">
  **When** AI エージェントが作業中の判断点でカードを書き出すとき、
  **the** カードストア **shall** プロジェクトルートの `.documi/cards/` 配下にカード1件につき1つの JSON ファイルとして永続化し、カード1件は問い・状況となぜ今か・何もしないとどうなるか・具体例・選択肢・仮置き可否に加えて、回答状態（選択肢・書き込みテキスト・仮置き/確定の別・回答日時）と異議・理解不能のフラグを同一ファイルに保持する。カード ID は英数字と `._-` のみとし、カードはちょうど1つの negative 選択肢を持たなければならず、仮置きできないカードを仮置きで回答することはできず、存在しない選択肢 ID では回答できない。`.documi/` は gitignore 済みの操作ストアであり、確定したカードは `<Decision>` 等として docs へ蒸留できる。蒸留は確定済みカードにのみ許可し、選択された選択肢・書き込み・判断材料を含む決定レコードを `docs/decisions/` に新規作成し、カードに `distilledAt` を記録する。蒸留済みカードの再蒸留は拒否し、出力先の決定レコードが既に存在する場合は上書きしない。既存レコードが今回生成すべき内容と完全一致するときは、決定レコード作成後に `distilledAt` の記録だけが中断した状態とみなして `distilledAt` を補完し、内容が異なるときは拒否する。
</Spec>


<Test id="test.core.review-card-store" level="unit" verifies="core.review-card-store">
  - **Given**: 一時ディレクトリをプロジェクトルートとするカードストア
    - **When**: カードの作成・取得・一覧・回答・フラグ更新・蒸留を行う
    - **Then**: 作成したカードが取得・一覧でき、negative 選択肢が1つでないカードは拒否され、仮置きできないカードへの仮置き回答は拒否され、存在しない選択肢 ID の回答は拒否され、`other` 選択では書き込みテキストが保存され、ルート外に脱出するカード ID は拒否される。確定していないカードの蒸留は拒否され、確定カードの蒸留では `docs/decisions/` に決定レコードが作られて `distilledAt` が記録され、蒸留済みカードの再蒸留と内容の異なる既存決定レコードの上書きは拒否され、生成内容と一致する既存レコードがある中断状態では `distilledAt` が補完される
</Test>

<Spec id="ui.review-card-distill" stability="volatile" derives="goals/human-comprehension">
  **When** ユーザーが `/cards` で確定済みの <Term name="ReviewCard" /> を見ているとき、
  **the** Web UI **shall** 確定済みカードにだけ「記録に残す」操作を表示し、その操作でカードの蒸留をサーバーへ要求する。蒸留に成功したカードは操作対象としての役割を終えたものとして一覧から取り除き、蒸留に失敗したカードは一覧に残して再試行できるようにする。未確定・仮置き・破損したカードには蒸留操作を表示しない。「記録に残す」は判断への応答ではなく確定後の記録完了操作なので、「意味がわからない」「納得いかない」「仮置き」「確定」の4つの判断ボタンには含めない。
</Spec>

<Test id="test.ui.review-card-distill" level="integration" verifies="ui.review-card-distill">
  - **Given**: 確定済み・仮置き・未回答の Review Card が混在する `/cards` 画面
    - **When**: 各カードの表示と、確定済みカードに対する「記録に残す」操作を行う
    - **Then**: 「記録に残す」操作は確定済みカードにだけ表示され、操作で蒸留 API が呼ばれ、成功したカードは一覧から取り除かれ、失敗したカードは一覧に残る
</Test>
