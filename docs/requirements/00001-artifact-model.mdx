# 要件

Documi は以下の 8 種類の Artifact を扱う。

| Type | Directory | 役割 |
|---|---|---|
| `goal` | `goals/` | プロダクトの目的・達成したい状態 |
| `requirement` | `requirements/` | 実現すべき機能・満たすべき条件 |
| `architecture` | `architecture/` | システム全体の構造・責務・境界 |
| `design` | `designs/` | Requirement を実現する具体的な設計 |
| `decision` | `decisions/` | 技術・設計上の選択とその理由 |
| `contract` | `contracts/` | API・Protocol・Data Format などの契約 |
| `verification` | `verification/` | 要件・設計・契約をどのように検証するか |
| `guide` | `guides/` | 利用方法・開発手順・運用方法 |

## 識別規則

- ファイル名は `NNNNN-kebab-case-slug.md` または `.mdx`
- ID は 5 桁の数字で、Artifact Type 内で一意
- 識別子は `type:id` の形式（例: `requirement:00001`）
- ID はファイル名から導出し、Frontmatter に重複して保存しない

## Frontmatter

必須: `type`, `title`, `description`, `status`。任意: `tags`, `sources`, `subtype`, `perspective`, `relations`。
`status` は `draft` / `accepted` / `deprecated` のいずれか。
